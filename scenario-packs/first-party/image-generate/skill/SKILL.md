# 图片生成

使用这项 Skill 把明确的视觉目标转化为一项可确认、可追踪的图片生成任务。

## 工作顺序

1. `prompt` 必须描述主体、环境、构图和必要限制。缺少会实质影响结果的信息时，只询问最关键的问题。
2. 只使用用户明确给出的尺寸、比例、质量、格式、背景、数量和参考图片。没有明确要求的可选参数交给已发布 Workflow 与 Provider Binding 决定，不臆造模型参数。
3. 参考图片只能来自当前可信上下文中的 Artifact；不得猜测、复用不可见资源或把资源 ID 写进回复。
4. 图片生成会启动制作并可能产生费用，必须调用运行时提供的 Workflow 提案 Tool。用户确认结构化提案前，不得声称任务已提交或图片已生成。
5. 确认后的运行、费用、取消、重试和结果以 Workflow、CapabilityRun、Artifact 与预算事实为准；Agent 不自行模拟进度或结果。
6. 用户提到本会话之前的任务或图片结果时，先读取当前会话的制作事实；有多个可能结果时必须让用户明确选择，不能默认使用最近一项。
7. 如果图片生成入口带有结构化不可用状态，严格按照其中的恢复建议说明下一步；如果只有 Tool 缺失而没有不可用状态，不得自行推断是模型、Provider、预算、权限或 Workflow 配置问题，只能说明当前无法发起制作并建议稍后重试或请管理员检查。不得创建空画板、改用无关底图或在文字中伪造付费确认。

## 完成标准

- 提案使用用户能判断的目标、比例、数量和影响说明，不展示 Workflow、Provider、模型、Tool 或内部 ID；
- 只有真实任务创建后才能说“已开始制作”；
- 只有真实 Artifact 可读取后才能说“结果已准备”；
- 失败时保留已有内容，说明可调整要求、再次制作或查看已有结果，不能伪造成功。
