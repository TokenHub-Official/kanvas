# ADR-0011：场景逻辑分层并维护第一方金丝雀场景

- 状态：Accepted
- 日期：2026-07-27

## 背景

Kanvas 不应把“海报”“电商主图”“社媒封面”等业务流程硬编码进平台内核，否则 Capability、Workflow 和产品导航会迅速与少数场景耦合。

但“核心无任何场景代码”如果被绝对化，也会让平台失去验证抽象的生产证据。没有第一方真实场景持续约束时，Capability 粒度、Workflow DSL、Artifact 血缘、审批和 Studio 交互都可能围绕假设设计，最终退化为功能完整但缺少专业判断的通用编排器。

## 决策

- 平台内核不硬编码具体行业场景流程。
- 项目至少维护两个第一方金丝雀场景包，覆盖差异明显的真实生产闭环。
- V0 金丝雀场景位于 monorepo 的独立 `scenario-packs/` 边界，通过公开 Capability、Workflow 和 Skill Profile 使用核心平台；场景包协议稳定后可以迁移到独立仓库。
- 内部品牌资料、Prompt、模板和业务数据可以保持私有，但场景契约、测试夹具结构和匿名化 Eval 方法应尽量进入开源仓库。
- 金丝雀场景同时承担产品示例、集成测试、架构验收和 Agent Eval，不只是演示数据。
- 新增平台抽象前，必须证明至少两个参考场景无法通过已有配置、Workflow 和 Capability 合理表达。

## 场景逻辑分类

### 必须以经过测试的代码存在

- 文件解析、MIME 检测、压缩包限制和恶意资产防护。
- 图像解码、渲染、转码、ICC 色彩和字体解析。
- 尺寸、安全区、版式、文字适配和导出校验引擎。
- Artifact 不可变内容、血缘、版本比较和交付打包。
- 权限、预算、审批、数据分类和数据出口策略。
- Browser Runtime、Worker、Provider Adapter 和路由回退。
- Studio 中比较、批注、审批、回退和可编辑文档的核心交互。
- 不能由受控 Workflow DSL 安全、可恢复表达的底层算法或基础设施行为。

这些代码属于通用平台或 Capability Implementation，而不是具体业务场景模块。

### 适合声明式 Workflow

- Capability 的先后顺序。
- 有限分支、有限 Map 和并行变体。
- 人工确认点。
- 输入参数映射和输出选择。
- 交付前的确定性质量门禁。

### 适合 Skill Bundle、配置或数据

- Prompt、Instructions 和 References。
- 尺寸集合、渠道规则和输出数量。
- 命名规则和交付清单。
- 品牌规则数据、模板和示例资产。
- 审批人、角色和 Workspace 策略引用。
- Workflow Entrypoint 与 Eval Case。

## 第一方金丝雀场景

V0 固定两个差异明显的场景：

1. 批量商品图基础处理：确定性生产流水线，覆盖 Browser 工具、有限 Map、Worker 回退、Mask 修正、部分成功、命名和打包。
2. 商品营销主图：非确定性创意决策链，覆盖确认 Brief、远程候选、人工选择、固定模板渲染和交付。

活动与社媒素材套图可以作为第三个候选，但不进入 V0 必须范围。

每个金丝雀场景必须包含：

- 真实 Brief 的匿名化样例与输入约束。
- 可量化的现有耗时、失败和返工基线。
- Workflow Revision 和所需 Capability 清单。
- 典型、边缘和失败输入。
- Artifact 血缘与预期交付物。
- 人工确认点和不可自动化判断。
- 成本、耗时、成功率和人工修改距离指标。
- Shadow Agent 的 Workflow 推荐和参数填充 Eval。

## 架构验收规则

- 两个场景共同需要的稳定语义才优先上升为通用 Capability 或平台能力。
- 只服务单一场景且可用配置表达的内容不得进入核心领域。
- 安全、可靠性、媒体解析和 Artifact 正确性不因“场景动态化”而下沉到不受信配置。
- V0 可以直接维护场景包源码和测试，不要求先建设 Marketplace、远程 Registry 或通用包依赖系统。
- 场景包升级必须发布新 Revision；历史 WorkflowRun 继续引用原 Revision。

## 结果

- 核心继续保持场景无关，内部私有流程和开源平台不需要长期分叉。
- 第一方真实场景持续验证 Capability 粒度、Workflow 表达能力和 Studio 体验。
- 场景包为 Shadow Agent、视觉 QA 和可靠性 Spike 提供稳定样例。
- 需要维护少量第一方场景和匿名化测试数据，但这属于产品与架构验收成本。

## 未包含

- 两个金丝雀场景的最终业务优先级。
- 私有素材和品牌数据的开源方式。
- 场景包的独立仓库或 monorepo package 布局。
- 公共场景 Marketplace 和第三方发布流程。
